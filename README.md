# Moodalyx — six-emotion text classifier (bidirectional GRU on dair-ai/emotion)

A portfolio project that began from a YouTube tutorial and was extended with a research interface, re-evaluation of the shipped model (per-class metrics, calibration, error analysis) and documented limitations. In short: a two-layer bidirectional GRU that predicts one of six emotion labels
(sadness, joy, love, anger, fear, surprise) for short English text, served by FastAPI with an HTML/CSS/JavaScript
research interface.

> The model predicts which of the dataset's labels a sentence most resembles. It does not measure anyone's
> emotional or psychological state, has no neutral class, and can be confidently wrong.

## Results (shipped artifact, dair-ai/emotion test split, n = 2,000)

| Metric | Value | Source |
|---|---|---|
| Accuracy | 0.921 | re-evaluated (`evaluation/evaluate_artifact.py`); matches notebook cell 33 |
| Macro-F1 | 0.880 | re-evaluated |
| Weighted F1 | 0.922 | re-evaluated |
| Expected calibration error (10 bins) | 0.048 | re-evaluated |

Per-label metrics, the confusion matrix, a reliability diagram and the most confident errors are in
`static/data/evaluation.json` and shown in the Evaluation section of the UI.

**Caveat:** the notebook used the test split as `validation_data` for early stopping, so the test score is
optimistically biased.

## Architecture

```
static/
  index.html                 research interface
  css/core.css, js/core.js   shared design system (synced from ../../_design_system)
  css/app.css, js/app.js     project UI
  data/evaluation.json       generated by evaluation/evaluate_artifact.py
main.py                      EXISTING FastAPI app + preprocessing + inference (unchanged)
Artifacts/                   BiGRU_Model.keras (41 MB), tokenizer.pkl (unchanged)
evaluation/                  NEW: evaluation script + its extra requirements
final_clean.ipynb            training notebook (unchanged)
```

No backend changes were needed: the UI uses the existing `GET /health` and `POST /predict`
(`{"text": "…"}` → `predicted_emotion`, `confidence`, `all_probabilites`). The previous Moodline UI in `static/`
was replaced; there was no Streamlit code in this project.

## Run locally

```bash
cd DL/EMOTION_TEXT_DL_NLP
python3.11 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
uvicorn main:app --port 8000
```

Open <http://localhost:8000>. Run the server from the project directory: `main.py` uses relative paths for
`Artifacts/` and `static/`.

**Apple Silicon / macOS:** `tensorflow-cpu` (pinned for Linux deployment) has no macOS wheels. Locally, install
the same versions with `tensorflow==2.17.0` instead:

```bash
pip install fastapi==0.115.0 "uvicorn[standard]==0.30.6" pydantic==2.9.2 tensorflow==2.17.0 numpy==1.26.4 h5py==3.11.0
```

### Regenerate the evaluation

```bash
pip install -r evaluation/requirements-eval.txt
python evaluation/evaluate_artifact.py
```

It downloads the dair-ai/emotion test split from Hugging Face, scores it through `main.preprocess_text`
(the API path) and through the raw text (the notebook path), and writes `static/data/evaluation.json`.

## Limitations

- Test split used for early stopping (see above); the dataset's validation split was not used.
- Training text is short English posts, mostly starting with "i feel …"; other domains are unreliable.
- Six forced labels and no neutral class; factual sentences still receive an emotion.
- Surprise (66 test examples) and love (159) are the weakest classes.
- Inputs are truncated to 50 tokens; words outside the 10,000-word vocabulary become `<unk>`.

## Deployment notes

- No API keys or secrets are needed.
- `Artifacts/BiGRU_Model.keras` is 41 MB: below GitHub's 100 MB limit, but consider Git LFS.
- `runtime.txt` pins Python 3.11.9; `requirements.txt` pins `tensorflow-cpu==2.17.0` for Linux hosts.

Dataset: Saravia et al. (2018), *CARER: Contextualized Affect Representations for Emotion Recognition*, EMNLP.
